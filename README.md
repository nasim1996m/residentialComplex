# نظام إدارة المجمع السكني

Next.js 16 + PostgreSQL + Prisma. كل البيانات (البيع، الأقساط، الاشتراكات، السيارات، الكراج، الصيانة، الموظفين) تُحفظ في قاعدة البيانات عبر API محمي بالصلاحيات.

## التشغيل

```bash
cp .env.example .env          # ضع رابط قاعدة البيانات وبيانات حساب الأدمن الأول
npm install
npx prisma migrate deploy     # إنشاء الجداول
npm run db:seed               # 7 بنايات، 100 شقة، الخدمات، وحساب SUPER_ADMIN
npm run build && npm start
```

## الصلاحيات

| الدور | ماذا يستطيع |
|---|---|
| SUPER_ADMIN | كل شيء: تسجيل البيع، إضافة/تعطيل الموظفين، أسعار الخدمات |
| ADMIN_STAFF | تسجيل دفع الأقساط والاشتراكات، إصدار فواتير الشهر، حالة السكن، السيارات والكراج |
| MAINTENANCE_WORKER | بلاغات الصيانة فقط (بدء التنفيذ ← تم الإنجاز) |
| RESIDENT | شقته فقط: الأقساط، الفواتير، سياراته، بلاغات الصيانة |

حسابات السكان والموظفين يُنشئها الأدمن، ويظهر للأدمن كلمة مرور مؤقتة مرة واحدة فقط ليسلمها لصاحبها. بعدها يغيّرها صاحب الحساب من أيقونة المفتاح.

## قواعد العمل

- الاشتراكات الافتراضية (الحراسة، النظافة، المصاعد) تُفعّل تلقائياً عندما تكون الشقة مسكونة (مالك أو مستأجر)، وتتوقف عند إخلائها.
- زر "إصدار فواتير الشهر" يُنشئ فاتورة واحدة لكل اشتراك فعّال في الشهر. تكرار الضغط لا يكرر الفواتير.
- جدول الأقساط يُحسب بالسنت: مجموع الأقساط مع الدفعة المقدمة يساوي سعر الشقة بالضبط.
- لا يُدفع القسط أو الفاتورة مرتين، حتى لو وصل الطلبان في نفس اللحظة.
- كل عملية حساسة تُسجل في جدول `AuditLog`.

## اختبار 100 ساكن

```bash
npx prisma migrate reset --force   # يمسح القاعدة ويعيد التهيئة — لقاعدة الاختبار فقط
npm run build && npm start &
BASE_URL=http://localhost:3000 npm run test:load
```

يبيع الاختبار 100 شقة عبر الـ API بأربعة أنظمة دفع، ويصدر فواتير شهرين، ويسجل الدفعات. بعدها يسجل دخول كل ساكن ويتأكد أنه لا يرى بيانات غيره، ثم يطابق كل الأرقام مباشرة مع PostgreSQL.
